## Findings

### F-1 — MAJOR: `deploy.yml` is deleted and Pages is already claimed as gated, violating the P00 acceptance bullet
`git status --short -- .github/` → `A .github/workflows/ci.yml` + `D .github/workflows/deploy.yml`; `git diff --cached --stat` shows `.github/workflows/deploy.yml | 50 -` (whole file removed). `README.md:122-126` now states "`.github/workflows/ci.yml` is the only workflow … there is no separate deployment workflow", and `ci.yml:63-88` already contains the folded Pages upload + deploy job. P00 acceptance (`IMPLEMENTATION-READY.md:102`) requires: "Pages deployment remains unchanged until P50; do not claim it is gated yet." The reviewed state does the opposite. The change itself matches P50 item 4 (`IMPLEMENTATION-READY.md:437-441`), so the defect is phase sequencing in the staged commit, not the fold itself. Two concrete consequences: (a) the runbook's own sequencing rule ("Pages deployment remains unchanged until P50") is broken in the artifact under review; (b) the old push-triggered Pages workflow is removed in the same change that adds its replacement, before any real CI run has been observed — the runbook itself requires "After the first successful real CI run … Local workflow text is not evidence that merge protection is active" (`:444-447`). Note also that `docs/refactor-implementation-findings/p00/baseline-record.md:40` still asserts "only `.github/workflows/deploy.yml` (Pages deploy, left untouched until P50)", which is false in the same staged tree.

### F-3 — MINOR: CI step order follows P50 §Final CI Sequence, not P00 item 7's literal ordering
P00 item 7 (`:88-90`) says "… format, lint, local Prisma validation, **the current test/typecheck commands, then both builds serially**". The staged `ci.yml:48-61` order is `typecheck:server → build:server → npm test → typecheck:demo → build:demo`, i.e. the P50 sequence (`:449-457`). The P00-literal order is unrepresentable once P30 splits `typecheck` into two target-specific checks and `npm test` itself regenerates demo entries. Substantively the requirement holds — every gate is a real npm script, the two builds are strictly serial, and no test runs after a build. Not a defect in the workflow, but it is a visible deviation from the phase's own wording.

### F-4 — MINOR: `package-lock.json` carries 27 unexplained `"dev": true` removals
`git diff --cached -- package-lock.json` shows exactly one intended addition (`node_modules/fake-indexeddb@6.2.5`, devDependency) plus **27** removals of `"dev": true` on optional platform binaries (e.g. `node_modules/fsevents` at diff hunk `@@ -9356,7`, and the per-arch `@next`/`oxide`-style entries at `:5389-5525`). Adding a devDependency does not make `fsevents` non-dev, and none of this is in the P00 change set. Most likely cause: the lockfile was rewritten by npm `11.17.0` (per `baseline-record.md:16`) while `package.json:10` pins `packageManager: "npm@11.6.0"`. No CI impact — `npm ci` installs dev dependencies — but it is unreviewed dependency-metadata churn that should be regenerated with the pinned npm or reverted.

### F-5 — MINOR: two remaining Prisma-validation invocation sites do not use `prisma:validate`
`REFACTOR_PLAN.md:219` → `prisma validate && prisma generate`; `docs/implementation/slice-02-handoff.md:115` and `:178` → `npx prisma validate`. Both bypass the npm script, contradicting item 6's "Invoke that script everywhere so validation always uses the repository-local Prisma CLI" and Delivery Order's "Use the repository-local Prisma CLI through npm scripts or `npm exec -- prisma`" (`:57-58`). Mitigating: `REFACTOR_PLAN.md` is a fixed requirement record the runbook demotes to evidence (`:3-7`) and P00 itself adds it to `.prettierignore` rather than editing it; `slice-02-handoff.md` is a historical handoff and is in neither the P50 doc list (`:426-433`) nor the P00 set. So the P00-governed docs are clean; this is documentation hygiene for a later pass.

### F-6 — MINOR: the escape regression leaks its parent temp directory
`tests/unit/clean-build-artifacts.test.ts:10` creates `parent` via `fs.mkdtempSync(path.join(os.tmpdir(), "clean-build-"))`, but the `finally` at `:31-35` removes only `root` and `outsideDir`. Every test run leaves an empty `clean-build-XXXXXX` directory in the OS temp dir. Benign, but a one-line `fs.rmSync(parent, ...)` would close it.

### F-9 — INFO: `prisma validate` runs in CI with no `DIRECT_URL` — cannot be confirmed read-only

The runbook's own P20 note (`:219-222`) shows Prisma 7.9.1 behaving non-obviously without a CLI datasource. Flagged for confirmation from a real CI run; not a static defect either way.
