## 1. The ruling, and the classification used

Preserving the currently-deployed system is **not a goal** of this refactor; breaking it during the rewrite window is acceptable and expected. So every dossier clause that spends effort protecting the status quo is charged as cost, not as safety, and must either be dropped or justified by a counterparty outside this repository. Note that this ruling is already the plan's own non-negotiable — `REFACTOR_PLAN.md:6` "zero legacy backward-compatibility requirement", `:21` "Because legacy backward compatibility is explicitly dropped, Generation A is purged in a single closed sweep" — so the conservatism below is not merely unwanted, it is **contrary to the fixed input**.

- **(A) internal-legacy compat** — protects this project's own past (migration history, deleted route trees, a demo store's existing shape, "don't let `main` go red"). **Drop.**
- **(B) external counterparty contract** — a live third party or real user holds the other end. **Keep; name the counterparty and the evidence.**
- **(C) correctness dressed as compat** — fails loudly or silently regardless of any legacy. **Reclassify; keep, and stop calling it conservatism.**

**Tally: 12 A, 4 B, 6 C (several C clauses bundle several dossier locations; one A row — branch-off-`main` — is A by classification but kept because it costs nothing).**
