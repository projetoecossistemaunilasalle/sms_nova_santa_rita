## Findings

**MINOR-1 — `marketing.module.css` purge is broader than "owners deleted in P10"**
`src/components/marketing/marketing.module.css` shrank 688 → 213 lines (23 selector classes removed). A module-scoped search of the archived base tree shows `marketing.module.css` had exactly three consumers at base — `src/app/(professional)/entrar/page.tsx`, `src/app/(professional)/entrar/recuperar/page.tsx`, `src/components/auth/sign-in-error.tsx` — and **none** of them referenced `primary`, `secondary`, `page`, `header`, `nav`, `hero`, `heroCopy`, `heroArt`, `heroActions`, `heroDescription`, `eyebrow`, `routeRing`, `missionBoard`, `dogMark`, `section`, `sectionInner`, `sectionHeader`, `missionGrid`, `missionCard`, `missionIndex`, `portalCta`, `footer`, or `formRow`. These selectors were already orphaned before this refactor (the landing route is a redirect stub at both base and HEAD: `git show 9467757:src/app/page.tsx` equals the current file). The result is correct and matches Fixed Decision #5 ("Purge dead ... CSS"), but it is slightly wider than the literal P40a wording. No gate, parser, or baseline was added.

**MINOR-2 — the added `mobileNavItem` declaration is functionally redundant**
`src/components/portal/portal.module.css:157-159` adds `.mobileNavItem { display: flex; }`, but `.navLink` already sets `display: flex` at `portal.module.css:99-100` with identical specificity, so the later rule recomputes the same value. The actual defect being repaired was that `styles.mobileNavItem` was `undefined` and interpolated the literal string `"undefined"` into the class attribute at `portal-navigation.tsx:37`; making the class defined is the fix, and the declaration is a harmless way to express the marker's intent. Risk is only that a future reader treats the `display` value as load-bearing.

**MINOR-3 — rollback is assign-only, not replace-and-prune**
`src/runtime/adult-portal-demo-store.ts:451` uses `Object.assign(this.state, before)`. This restores every snapshot value in place and preserves object identity, but it would not remove a *new* top-level key introduced by a failed transaction. `DemoAdultPortalState` has a fixed top-level key set and no current code path adds one, so this is not a live defect; it is a latent asymmetry if the seed shape ever gains a collection.

**MINOR-4 — two persistence symbols became public only for the new test**
`src/runtime/offline/indexed-db.ts:54` (`openDatabase`) and `:119` (`IndexedDbGameOfflinePersistence`) are `export`ed; both were module-private at base (`git show 9467757:src/runtime/game-offline-sync.ts:564,647`). The widened surface is justified: the new lifecycle test asserts the production `expected_revision` normalization (`indexed-db.ts:259-263`), which is not observable through `GameOfflineStore`. This is not an export-path snapshot (the runbook's prohibition) — it is a real behavioral assertion against the production class.
